# 🏀 Hoops Name Generator · AI Basketball Player Name Generator

A deep learning-powered web application that generates unique, realistic, and creative basketball player names. The character-level LSTM is trained with PyTorch and runs directly in the browser, and it is also available through a FastAPI backend. The project features an interactive, basketball court-themed UI with real-time temperature (creativity) control and a personal favorites roster.

## 📌 Features

* **Character-Level Deep Learning Model:** Generates brand-new player names based on patterns learned from every player in NBA history. First and last names are modeled separately, and names that already belong to a real player are filtered out.
* **Dynamic Temperature Control:** Real-time creativity adjustment via a custom basketball-themed slider (0.20 to 1.20).
* **Favorites Roster:** Save any generated name to a persistent personal roster with a single tap on the star icon, browse your saved names in a dedicated roster view, and remove them individually whenever you like.
* **Runs Entirely in the Browser:** The trained LSTM is exported to JSON and executed in plain JavaScript, so the live site is a free, serverless static deployment on Vercel with no cold starts.
* **FastAPI Backend:** The same model is also served through a REST API (`/api/generate`) for local use and integrations.
* **Basketball Court-Themed UI:** Wood-grain background, chalkboard-style typography (Anton, Oswald, JetBrains Mono), and leather-accented components for an immersive court aesthetic.
* **One-Click Reset:** Instantly reset inference temperature back to the optimized default (0.70).

## 🚀 Quick Start

### 1. Clone the Repository

```bash
git clone https://github.com/egemenilerigelen/hoops-name-generator.git
cd hoops-name-generator
```

### 2. Create & Activate Virtual Environment

```bash
# On Windows
python -m venv venv
.\venv\Scripts\activate

# On macOS/Linux
python3 -m venv venv
source venv/bin/activate
```

### 3. Install Dependencies

```bash
pip install -r requirements.txt
```

### 4. Run the Application

Launch the FastAPI server using Uvicorn:

```bash
python -m uvicorn app:app --reload
```

Open your browser and navigate to:

```
http://127.0.0.1:8000
```

The page generates names in the browser using `static/model.json`, exactly like the live site. The REST API runs alongside it (see [API](#api)).

To preview only the static site, as Vercel serves it, without installing Python dependencies:

```bash
python -m http.server 8000 --directory static
```

### 5. (Optional) Retrain the Model

```bash
pip install -r requirements-dev.txt
python train.py            # retrain and re-export static/model.json
python train.py --scrape   # re-fetch the NBA player list first
python -m src.generator    # print sample names from the saved checkpoint
```

### 6. Run the Tests

```bash
python -m pytest
```

## 🧠 Model & Architecture

* **Model size.** Embedding (32) → 2-layer LSTM (hidden 128, dropout 0.2) → Linear, about 220k parameters over a 32-token vocabulary (28 characters + 4 special tokens), trained on 5,063 cleaned NBA names.
* **Conditional character-level LSTM.** Each first or last name is a sequence `[BOS] c₁ c₂ … cₙ [EOS]`. Two distinct start tokens (`BOS_FIRST`, `BOS_LAST`) let a single network learn both distributions, so first names sound like first names and surnames sound like surnames.
* **Full-sequence training (teacher forcing).** The model sees the whole name at once and is trained with cross-entropy on the next character at every position; padding is ignored in the loss. A held-out validation split drives early stopping, and the best epoch is kept.
* **Stateful generation.** During sampling the LSTM hidden state is carried from character to character, so each prediction is conditioned on the entire prefix, not a fixed window.
* **Novelty filter.** Generated names that match a real player (including suffix-free forms such as *Gary Payton* for *Gary Payton II*) are rejected and resampled, as are names longer than the UI card can display.
* **Self-contained checkpoint.** `models/lstm_weights.pth` stores the weights, vocabulary, model hyperparameters and the known-name list. Inference never reads the data files, and it loads with `torch.load(..., weights_only=True)`.
* **Modular design.** `Checkpoint` is the only class that knows the on-disk format, `Trainer` and `NameGeneratorService` receive their dependencies through constructors, file I/O is isolated in `io_utils.py`, and the API resolves the generator via FastAPI `Depends`. See [docs/PROJECT_CONTEXT.md](docs/PROJECT_CONTEXT.md) for details.

### API

| Endpoint | Description |
|---|---|
| `GET /` | Serves the frontend (`static/`: `index.html`, `name-generator.js`, `model.json`). |
| `GET /api/generate?temperature=0.7` | Returns `{"name": "...", "temperature": 0.7}`. `temperature` must be within `0.1 – 2.0` (otherwise `422`). |
| `GET /api/health` | Liveness check. |

Interactive API docs are available at `http://127.0.0.1:8000/docs`.

## ☁️ Deployment (Vercel)

The live site is fully static: `static/` (HTML, `name-generator.js`, `model.json`) is served by Vercel's free Hobby plan, and the LSTM runs in the visitor's browser, so hosting costs nothing.

* **Production:** every push to `main` is deployed to [hoops-name.vercel.app](https://hoops-name.vercel.app) through Vercel's GitHub integration.
* **Previews:** every other branch and pull request gets its own preview URL, so changes can be tried before merging.
* `vercel.json` (no framework, no build, output `static/`) and `.vercelignore` ensure only the static site is uploaded, so Vercel never tries to run the FastAPI/PyTorch backend.

`.github/workflows/ci.yml` runs the test suite on every push and pull request, including a check that the JavaScript forward pass matches PyTorch and that `model.json` is in sync with the checkpoint.

After retraining, commit both `models/lstm_weights.pth` and `static/model.json` (`train.py` regenerates the latter automatically; `python -m src.web_export` does it manually).

## 🎯 How Temperature (Creativity) Works

The temperature parameter scaling dictates the randomness of character probability distributions during sampling:

| Range | Behavior |
|---|---|
| **Low (0.20 – 0.50)** | Predictable, conventional, and highly realistic names. |
| **Balanced (0.70 — Default)** | Optimal balance between realism and novelty. |
| **High (0.90 – 1.20)** | High variance, wild, and creative combinations. |

## ⭐ Favorites Roster

Every generated name can be saved to your personal roster:

* Tap the **star icon** on a generated name to add or remove it from your favorites.
* Tap **ROSTER** in the header to switch to your saved list, and **← GENERATE** to return to the generator.
* Each roster entry can be removed individually with its **✕** button.
* The roster is stored locally in the browser, so it persists between visits on the same device.
